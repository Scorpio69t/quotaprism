# ADR-0006：M1 刷新调度器

- 状态：Accepted
- 日期：2026-11-27

## 背景

M1 需要在接入真实 Provider 前建立刷新节流、并发和失败语义，避免实现后期再重写账户刷新与通知逻辑。

## 决策

- 新增独立 `prism-scheduler` crate，不依赖 Tauri、HTTP、SQLite 或真实 Provider。
- 调度器注入 `Clock`，支持系统时钟与确定性 fake clock；冷却、退避和状态快照均以注入时间计算。
- 同一账户只允许一个进行中的刷新；同账户并发调用等待并共享同一结果；不同账户独立刷新。
- 错误分类包含认证、权限、429、网络、超时、schema、不支持、存储、取消、未知和冷却跳过。
- 认证、权限、schema、不支持、存储和取消不进入通用指数退避；429 使用 Retry-After；网络、超时和未知使用指数退避并设上限。
- 取消通过显式 `RefreshControl` 传播，取消前不执行刷新动作，不伪造成功。

## 后果与限制

- 当前调度器不建立后台线程、HTTP 请求、Provider 注册或持久化状态；只提供同步刷新核心、并发合并和内存状态。
- 测试覆盖 401、429、超时、取消、singleflight 和跨账户独立执行；实际异步请求、Tokio cancellation、睡眠恢复和持久化刷新状态留待后续。
