# ADR-0003：M1 SQLite 本地存储

- 状态：Accepted
- 日期：2026-11-27

## 背景

M1 需要持久化账户与最近成功快照，同时保持 Core 独立于桌面和数据库。该存储只服务本地应用，不引入真实 Provider、凭据或未来配置模块。

## 决策

- 新增独立 `prism-storage` crate，使用同步 `rusqlite`；Tauri 调用前应通过短生命周期工作线程或应用服务，不在 Tokio runtime 中阻塞。
- 单库启用外键，文件数据库启用 WAL。迁移使用 SQLite `user_version` 和显式事务，任一迁移失败回滚，禁止部分迁移状态。
- v1 包含 `accounts` 与 `quota_snapshots`；快照按 `account_id` 保留最近成功规范化 JSON，只覆盖同账户最近快照，不按单位或供应商混合数据。
- 账户写入与快照覆盖在同一事务中提交；账户删除级联删除快照。存储不保存原始 HTTP 响应、认证输入、密钥或 keychain 引用之外的凭据。
- 存储错误以稳定 Rust 类型返回，不伪造空账户、百分比或快照；未知数据保持现有 DTO 的 `null`/未知语义。

## 后果与限制

- 当前仓储只实现账户、最近快照、重启读取与删除，是 M1 第一个垂直切片，不包含刷新状态、通知去重、设置或历史保留。
- 临时数据库测试覆盖迁移、重启读取、删除和迁移失败回滚；目标 OS 的文件位置、权限、WAL恢复与并发仍需实际验收。
- 未来迁移可能拆分规范化表或增加刷新状态，但必须保持迁移事务和账户删除一致性。
